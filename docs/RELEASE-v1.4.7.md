# v1.4.7 · 小米账号持久登录修复

> 本版修复小米渠道保存账号后仍几乎每次都要重新授权的问题。修复覆盖“小米扫码登录”和“小米官方网页登录”两条入口。

## 根因

- 小米扫码登录此前只保存 AnySDK `/v1/login` 返回的短期 `session`，没有保存小米 OAuth `/misdk/v2/oauth` 返回的 `{uuid, st}`。
- AnySDK 会话过期后，本地记录里没有可重新调用 `getLoginAppAccount_v2` 的材料，只能重新扫码。
- “小米官方网页登录”走宿主的 `ChannelCore.connect`，此前只保存账号资料，没有写入直登引擎的登录会话。
- 旧记录中的 `session` 是 SGS / AnySDK 会话，不能当作小米 OAuth 服务令牌使用。

## 修复方式

- 在直登引擎中校验并持久化小米 OAuth `{uuid, st}`：
  - `uuid` 必须为 1–20 位数字；
  - `st` 必须非空、长度不超过 4096，且不包含表单分隔符、等号或换行。
- 扫码登录取得 OAuth 后不再删除 `st`，而是与原生游戏会话、SGS 会话一起保存。
- 恢复账号时：
  1. 优先复用仍可用的已保存会话；
  2. 原生游戏会话被拒时，用保存的 `uuid/st` 重新调用 `getLoginAppAccount_v2`；
  3. SGS 会话被拒时刷新一次原生游戏会话并重试；
  4. 仅当 `st` 确实失效时要求重新授权，并保留账号记录。
- 新增 `rememberBrowserSession` 直登引擎接口。官方网页登录成功后，会把同一账号记录所需的 OAuth 令牌、原生游戏会话和 SGS 会话写入本地存储，并复用已有记录 ID 与创建时间。
- 官方网页登录返回的 `restore` 在写入存储后立即从交接参数中移除，不会进入 `LAUNCH`、游戏 URL 或客户端参数。
- 关闭“保存登录信息”时不写入这些凭据；删除账号时仍按原有流程清除本地会话。

## 测试记录

- 新增 `tests/_test_xiaomi_saved_session.js`，覆盖：
  - 扫码与官方网页登录保存 `{uuid, st}`；
  - 非法或含控制字符的令牌不落盘；
  - 官方网页登录更新同一账号记录；
  - 新鲜 OAuth 登录在兑换后保留 `uuid/st`；
  - 仅凭 `xiaomiOAuth` 自动换取游戏会话；
  - AnySDK 会话过期后刷新并成功恢复；
  - `st` 失效时要求重新授权且保留账号记录；
  - 关闭保存登录信息时不写入。
- `npm test`：39 项测试全部通过。
- `node --check _direct_engine.js` 与 `node --check 三国杀多渠道登录.user.js` 通过。
- `npm run sync:engine` 已同步主脚本中的嵌入引擎。

## 验证边界

- 尚未使用真实小米账号验证跨过期周期的端到端续期。本次结论来自现有协议调用、代码级测试和本地会话恢复测试。
- 如果小米服务端主动吊销 `st`、要求重新实名认证或触发风控，仍必须由账号本人重新授权；这是正常的安全边界。
- 升级前已经保存、但没有 `xiaomiOAuth` 的旧记录无法追溯续期。升级后需要成功授权一次，之后的恢复才会具备自动续期能力。

## 安装或升级

- 下载 Release 中的 `sanguosha-channel-login.user.js`，在 Tampermonkey 中覆盖安装。
- 安装后刷新登录页，页脚应显示 `v1.4.7 · 9 个渠道`。
- 不要同时启用旧版统一登录器或其他会向同一页面注入登录面板的脚本。
